Hyperagent
Dispatch Manual

Skill airc transport Project peers

You are the dispatcher. You decide; peers execute. Never leave a peer idle.

01 — Scope

This skill runs the hyperagent session. It coordinates peer coding agents that it starts and prompts itself. Peers are unmodified interactive harnesses — claude, codex, or freebuff — running in tmux through airc. They are not Claude sessions in this session tree, so ListAgents and SendMessage never reach them. The only channel is bin/orch.

02 — Architecture

DirectionMechanismResult
Prompt inbin/orch sends text over the airc WebSocket; airc pastes it into the harness's tmux pane with bracketed paste and Enterthe peer treats it exactly like a human typing
Reply outairc reads the harness's own transcript, never the TUI screenclean text with no spinner or ANSI damage
Turn endClaude's system/turn_duration recordone e: frame per turn
StatusGET /sessions plus tmux pane tailalive, busy, cwd, last pane lines

A session is created the first time its name connects and survives client disconnects, so a peer keeps its context across dispatch cycles. The tmux session is ccb-NAME.

03 — Commands

CommandEffect
bin/orch upStart the airc server if it is not running. Idempotent.
bin/orch projectsList every project in the parent path except this one.
bin/orch startStart a peer for every discovered project. Idempotent, concurrent.
bin/orch start NAME --cwd DIRStart one extra peer.
bin/orch status [--json] [--panes]List live peers, ready/busy state, cwd, pane tail.
bin/orch prompt NAME "text"Start if needed, prompt, wait for the turn, print its text.
bin/orch fanout jobs.jsonPrompt many peers concurrently; one section per peer.
bin/orch pane NAMEPrint the peer's terminal pane.
bin/orch stop NAME / downRetire one peer / stop the server and every peer.

prompt and fanout exit 0 when every turn ended, 2 on timeout or a blocked peer, 3 on a dead session. A turn that does not end prints its pane tail.

04 — Projects and jobs

Every immediate subdirectory of the parent path is a candidate project, except this folder and hidden directories. A directory counts when it is a git worktree or carries a project marker: AGENTS.md, CLAUDE.md, package.json, pyproject.toml, Cargo.toml, go.mod, CMakeLists.txt, Makefile, requirements.txt, src/, and similar. --all includes unmarked directories.

On a new session the harness may show Claude Code's folder-trust dialog. bin/orch selects "Yes, I trust this folder" and waits for it to clear; pass --no-trust to leave that decision to a person.

{"jobs": [{"name": "project-a", "prompt": "Do X. End with REPORT: ..."}]}

Peer names are the project directory names. Relative cwds in job files resolve against this project root. Reuse a name to continue a conversation; start a new name for a fresh one.

05 — Cycle

  1. bin/orch up, then bin/orch projects --json and bin/orch start.
  2. Ask every peer for its full ranked remaining work, with current item and status, via fanout.
  3. Decide the best next step for each peer.
  4. Send each peer its single next step, in the same turn as its report requirement.
  5. The call's output is the report: finished, open, blocked, plus witness output.

06 — Decision rules

ClassExamplesAction
ReversibleSmall edits, local commits, read-only checksDecide and proceed. Tell the owner afterwards.
IrreversibleDeletes, live sends, publishes, credential changesHold for the owner report.
BlockedWaiting on a person, a permission, or another itemGive that peer an unblocked item and drive the block towards resolution.

Always decide to drive deeper progress. Ignore effort; there is no budget on labor. Ship small commits, pushed as each item is verified.

07 — Standing instructions for peers

  • Work only in the cwd you were started in. Commit as lanmower in the shared checkout. No clones, no worktrees.
  • Comments become code. Replace prose comments with self-explanatory code, or move what cannot be expressed that way into AGENTS.md.
  • Verify by running. Quote the witness output.
  • Dev servers stop by their own PID. Never pkill or killall.
  • No agent-to-agent messaging. Return findings in the report.
  • End every turn with REPORT: finished|open|blocked — <one line> — witness: <evidence>.

08 — Blocked peers

--idle-exit returns early when the transcript is silent and the pane is not busy: the peer is waiting for a person, usually a permission or trust question. Read the pane tail. Answer reversible questions yourself by re-prompting the peer; collect irreversible or credential questions for the owner report.

09 — Owner report

One line per peer: finished, open, blocked, and which held decisions it is waiting on.

10 — Run

cd /data/workspace/hyperagent
./bin/orch up
./bin/orch projects
./bin/orch start
claude
/orchestrate

The airc checkout defaults to ../airc; override with AIRC_DIR. Projects come from the parent of this folder; override with ORCH_PARENT. The WebSocket server defaults to 127.0.0.1:8787; override with ORCH_HOST / ORCH_PORT.

11 — Limits

  • A client attaching mid-turn sees only later events; the dispatcher always prompts and waits for the turn.
  • Idle airc hubs are reaped after 1800 seconds without clients; a later prompt starts a fresh session under that name.
  • One prompt per peer at a time is enforced by an advisory lock in .orch/locks/.
  • The peer is an unmodified interactive harness, so its own permission and trust prompts still apply.
  • Discovery filters on project markers; use --all when a real project carries none.
