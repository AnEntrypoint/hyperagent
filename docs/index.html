Hyperagent
Dispatch Manual

MCP tools airc transport Claude Code peers

You are the dispatcher. You decide; peers execute. Never leave a peer idle.

01 — Scope

This project opens as a Claude Code session with the hyperagent MCP server attached. The server starts peer Claude Code sessions in the projects beside this one, prompts them, and returns their turns. Peers are unmodified interactive harnesses running in tmux through airc. They are not Claude sessions in this session tree, so ListAgents and SendMessage never reach them.

02 — Architecture

DirectionMechanismResult
Tool callClaude Code calls mcp__hyperagent__*; the stdio server runs bin/orchone orchestration layer for MCP and CLI
Prompt inairc pastes text into the peer's tmux pane with bracketed paste and Enterthe peer treats it as a human typing
Reply outairc reads the harness's own transcript, never the TUI screenclean text with no spinner or ANSI damage
Turn endClaude's system/turn_duration recordone e: frame per turn
StatusGET /sessions plus tmux pane tailalive, busy, cwd, last pane lines

A session is created the first time its name connects and survives tool calls, so a peer keeps its context across dispatch cycles. The tmux session is ccb-NAME.

03 — MCP tools

ToolEffect
list_projectsList every project in the parent path except this one. Launches nothing.
start_projectsStart Claude Code peers for the named projects only (names).
instructPrompt one peer and wait for its turn. Starts it if needed.
instruct_manyPrompt many peers concurrently (jobs) and collect every turn.
turn_resultCollect a background turn started with wait: false.
resume_projectContinue a project's saved conversation in claude, codex or freebuff. No project means the last project and harness; no session_id means its newest session.
list_project_sessionsList resumable sessions per harness for a project, or every project with all: true.

stop_peer / server_downRetire one peer / stop the server and every peer.

A turn that ends returns the peer's text with status turn_end. Any other status (timeout, blocked, died) returns the pane tail. Open the project with bin/open so a tool call gets a 30-minute timeout; otherwise use wait: false and turn_result.

04 — Projects

Every immediate subdirectory of the parent path is a candidate, except this folder and hidden directories. A directory counts when it is a git worktree or carries a project marker: AGENTS.md, CLAUDE.md, package.json, pyproject.toml, Cargo.toml, go.mod, CMakeLists.txt, Makefile, requirements.txt, src/, and similar. Pass all: true to include unmarked directories.

Peer names are the project directory names. start_projects starts only the names the instruction gives; nothing launches implicitly. Peers stay alive between cycles, so start a name once. On first creation the server answers Claude Code's folder-trust dialog; pass trust: false to leave that decision to a person.

instruct_many {"jobs": [{"name": "project-a", "prompt": "Do X. End with REPORT: ..."}]}

04.1 — Resume

Each harness keeps saved conversations in its own store. A stopped peer can continue one instead of starting over:

resume_project {"prompt": "Continue the migration. End with REPORT: ..."}
resume_project {"project": "project-a", "session_id": "83e12101-..."}
resume_project {"project": "project-a", "harness": "codex"}
resume_project {"project": "project-a", "fork": true}
HarnessSession storeLaunch
claude~/.claude/projects/<slug>/<id>.jsonlclaude --resume <id>
codex$CODEX_HOME/state_*.sqlite threads, plus legacy rolloutscodex resume <id>
freebuff~/.config/manicode/projects/<name>/chats/<id>/chat-messages.jsonfreebuff --continue <id>

With no project, the last project touched is used; that ledger lives in .orch/state.json and remembers each project's cwd and harness. With no session_id, the project's newest session in that harness is resumed. list_project_sessions shows the candidates per harness. Resume retires a live hub or leftover ccb-NAME tmux session, restarts the airc server when needed, and launches the harness's resume form. The resumed store is read from its end, so a turn returns only the new reply, not the saved history. start_projects, instruct and instruct_many accept resume: true and harness to do this automatically when a peer is not running. The CLI is bin/orch resume [NAME] [--harness H] [--session ID] and bin/orch sessions [NAME] [--harness H] [--all].

Add fork: true / --fork to resume into a new session id instead of reusing the source; Claude uses --fork-session and codex uses fork. The source store is untouched and the new id becomes the project's remembered session.

Codex and freebuff need their own CLI login before a peer can run.

05 — Cycle

  1. list_projects.
  2. start_projects for the peers this instruction calls for. Never start a peer with no work for it.
  3. Ask every started peer for its full ranked remaining work, with current item and status, via instruct_many.
  4. Decide the best next step for each peer.
  5. Send each peer its single next step, in the same turn as its report requirement.
  6. The call's output is the report: finished, open, blocked, plus witness output.

06 — Decision rules

ClassExamplesAction
ReversibleSmall edits, local commits, read-only checksDecide and proceed. Tell the owner afterwards.
IrreversibleDeletes, live sends, publishes, credential changesHold for the owner report.
BlockedWaiting on a person, a permission, or another itemGive that peer an unblocked item and drive the block towards resolution.

Always decide to drive deeper progress. Ignore effort; there is no budget on labor. Ship small commits, pushed as each item is verified.

07 — Standing instructions for peers

  • Work only in the cwd you were started in. Commit as lanmower in the shared checkout. No clones, no worktrees.
  • Comments become code. Replace prose comments with self-explanatory code, or move what cannot be expressed that way into AGENTS.md.
  • Verify by running. Quote the witness output.
  • Dev servers stop by their own PID. Never pkill or killall.
  • No agent-to-agent messaging. Return findings in the report.
  • End every turn with REPORT: finished|open|blocked — <one line> — witness: <evidence>.

08 — Blocked peers

idle_exit_s returns early when the transcript is silent and the pane is not busy: the peer is waiting for a person, usually a permission question. Call read_pane and decide. Answer reversible questions yourself by re-prompting the peer; collect irreversible or credential questions for the owner report. A timeout does not cancel the peer's turn: check peer_status before prompting again.

09 — Owner report

One line per peer: finished, open, blocked, and which held decisions it is waiting on.

10 — Open

cd /data/workspace/hyperagent
./bin/open

bin/open starts Claude Code in this project and sets MCP_TOOL_TIMEOUT=1800000. The server is registered by .mcp.json and enabled by .claude/settings.json (enabledMcpjsonServers). Then run /orchestrate. The CLI equivalent is bin/orch: projects, start NAME, prompt, fanout, status, pane, stop, down.

The airc checkout defaults to ../airc (AIRC_DIR), projects come from the parent folder (ORCH_PARENT), and the server listens on 127.0.0.1:8787 (ORCH_HOST / ORCH_PORT).

11 — Limits

  • One tool call waits for one turn; bin/open raises the client timeout to 30 minutes.
  • A client attaching mid-turn sees only later events; the tools always prompt and wait for the turn.
  • One prompt per peer at a time is enforced by an advisory lock in .orch/locks/.
  • Two peers should not share one cwd: the Claude transcript channel binds the newest session file per project directory.
  • Discovery filters on project markers; pass all: true when a real project carries none.
